main.js Refactor Plan — progress log
====================================

State after Round 2: `js/app/main.js` is 1,447 lines (was 5,336 at the
start, 4,040 after Round 1). The 73% reduction came in two waves:

Round 1 (leaf extractions, no shared-state module yet)
- Pulled out cohesive blocks that touched little state, leaning on the
  `configure(deps)` pattern when a module still needed host callbacks.
- Result: main.js 5,336 → 4,040 (24%).

Round 2 (introduce `js/state/runtime.js`, then sweep)
- All 38 module-level `let` bindings (studyMode, deck, selectedKeys,
  globalWordMarks, appUsageStats, etc.) move into a single mutable
  `runtime` object in `js/state/runtime.js`. main.js no longer
  declares any top-level state.
- A Perl sweep with negative lookbehind (`(?<![.\w])`) for property
  accesses and negative lookahead (`(?!\s*:)`) for object-literal keys
  rewrote every bare reference to `runtime.X`. A handful of shorthand
  object-literal entries were expanded to explicit form first so the
  sweep wouldn't produce invalid `{ runtime.X }` syntax. Two `marks`
  parameter shadows were renamed to `marksMap`. A few prose strings
  the regex mangled ("Required-only runtime.deck") were restored.
- Once state lived in one place, the remaining hot-path blocks moved
  out one at a time: progress, render, selectors, navigation,
  analytics, persistence.
- Result: main.js 4,040 → 1,447 (additional 64% off Round 1's number,
  73% off the original).

Patterns to follow when adding new modules in the future
--------------------------------------------------------
1. Shared state goes on `runtime` in js/state/runtime.js. Don't
   reintroduce module-level `let` bindings in main.js.
2. A new UI module that needs host helpers exports `configureFoo(deps)`
   and stores the deps in a module-local `host` object. main.js wires
   it up at the top alongside the other configure* calls.
3. Modules that need to call into another UI module's functions
   import them directly (e.g. analytics.js imports renderProgress from
   progress.js). Avoid going through main.js as a relay.
4. onclick handlers in index.html are still satisfied by
   GLOBAL_CLICK_HANDLERS at the bottom of main.js; new handlers must
   be added there even if their implementation lives in a module.
5. Bump CACHE_NAME + every ?v= in sw.js and index.html when deploying.
   The service worker uses `caches.match(req, { ignoreSearch: true })`
   so bare ES module imports still resolve to versioned precache entries.
